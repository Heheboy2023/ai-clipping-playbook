# The AI Clipping Playbook — Companion Repository

Clipkit is the local, testable reference workflow that accompanies *The AI Clipping Playbook*. It turns authorized media into review-ready clips with FFmpeg, structured prompts, resumable batches, explicit human gates, and reproducible manifests.

Clipkit runs locally. It can inspect, cut, reframe, caption, normalize, check, and package media, but it has no upload, scheduling, or publishing command.

**Current release:** `v0.1.0`

## What is included

- A Python CLI with stable JSON output and useful exit codes.
- FFmpeg-backed cutting, vertical crop/pad, caption burn, audio normalization, and concat workflows.
- Local Whisper transcription plus transcript and candidate validation.
- Bounded batch processing and a resumable end-to-end pipeline.
- Rights-safe synthetic media fixtures generated by FFmpeg.
- Prompt contracts for ChatGPT, Codex, and Claude Code.
- Schemas, intake/review templates, business worksheets, tests, and troubleshooting notes.
- Six adaptable examples: podcast, YouTube-style local video, livestream/VOD, gaming, multi-speaker podcast, and batch production.

## Quick start

Python 3.11 or newer, FFmpeg, and ffprobe are required. Start with [the installation index](docs/installation.md) or the [complete beginner walkthrough](docs/beginner-walkthrough.md).

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python scripts/generate_fixtures.py
clipkit doctor
python -m pytest
clipkit run --manifest examples/end-to-end/job.yaml --dry-run
```

Windows PowerShell uses `.venv\Scripts\Activate.ps1`; see [the Windows guide](docs/windows-install.md).

## A safe first render

```bash
clipkit run --manifest examples/end-to-end/job.yaml
clipkit qc --batch work/end-to-end/run-state.json
```

Watch every generated file and compare it with the source. Only then record local QC:

```bash
clipkit approve --run work/end-to-end/run-state.json --reviewer "your name" --notes "full playback complete"
clipkit package --run work/end-to-end/run-state.json --destination generic-vertical --output work/end-to-end-package
clipkit validate-package --path work/end-to-end-package
```

That approval permits packaging only. It does not grant publishing authority.

## Repository map

| Path | Purpose |
|---|---|
| `src/clipkit/` | Tested CLI implementation |
| `scripts/clipkit/` | Thin chapter-friendly wrappers |
| `examples/` | Generated fixtures and reusable workflows |
| `prompts/` | Transcript, candidate, Codex, and Claude Code contracts |
| `schemas/` | Machine-readable data contracts |
| `templates/` | Intake, review, production, publishing-record, and business worksheets |
| `docs/` | Installation, commands, workflows, safety, and troubleshooting |
| `tests/` | Unit and FFmpeg integration tests |
| `REPOSITORY_MANIFEST.csv` | Every tracked file mapped to the chapters that teach it |

User media and generated work belong in `work/`, which is ignored. Do not place credentials, client secrets, or irreplaceable masters in the repository.

## Releases and downloads

Stable source archives and release notes are available on the [GitHub Releases page](https://github.com/Heheboy2023/ai-clipping-playbook/releases). Start with the newest tagged release. The default branch can contain documentation corrections made after a release, so use a tagged archive when you need a reproducible book workflow.

The release archive does not include generated work, private media, credentials, or a prebuilt Python environment. Follow the installation guide after download, generate the rights-safe fixtures locally, and run the test suite before using Clipkit on authorized media.

## Important boundaries

- Confirm rights and authorization before intake or retrieval. This project does not decide fair use and is not legal advice.
- AI scores are editorial heuristics, not predictions or performance guarantees.
- Speaker labels, transcript wording, boundaries, crops, captions, and audio require human verification against source media.
- `retrieve-metadata` records a small sanitized metadata set and downloads no media.
- Never expose real API keys. `.env.example` contains names only; `doctor` reports presence, never values.
- Keep platform specifications in recheck records because limits and policies change.
